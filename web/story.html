How a simulator caught a Raft bug before it shipped

Halyard · consensus · deterministic simulation

Halyard's Raft implementation is a pure state machine: no goroutines, no clock, no network. That makes it possible to run an entire cluster inside one test, on a virtual clock, with a network that drops, duplicates, delays and reorders messages, and nodes that crash at random — all derived from a single seed. After every step the simulator checks Raft's safety properties.

One seed, out of the first hundred of the membership test, failed with this:

seed 15 t=846: STATE MACHINE SAFETY: index 71 applied as t4/0/ on n3 but t3/0/ elsewhere

Two replicas had applied different entries at the same log position. In a consensus system that is the one thing that must never happen.

What happened

The cluster started with nodes 1–3; node 4 was then added with AddNode(4). Node 4 started empty and received the log from the leader, entry by entry. The membership of the original three nodes, however, came from a command-line flag on each of them — it was never written into the log.

Node 4 applied AddNode(4) and concluded the voter set was {4}. A quorum of one is trivially reached, so after an election timeout it voted for itself, became leader, and committed entries on its own. Meanwhile nodes 1–3 elected their own leader and committed different entries at the same indexes. Two leaders, two histories.

The fix

Anything a node uses to make decisions must come from the replicated log, not from local configuration. The founding members are now written into the log as committed configuration-change entries at indexes 1..n, byte-identical on every founding node — the same approach etcd uses. A node that joins later replays them and learns the full membership. On restart, membership is rebuilt from the snapshot plus committed entries, never from flags.

The general lesson: in a replicated system, every input that affects a decision must be replicated. Local flags, clocks and environment are ways for replicas to disagree.

Why this matters

Integration tests with three healthy nodes would never have hit this: it needs a membership change, a specific message ordering and a timeout to line up. The simulator explores thousands of such schedules per run, and every failure comes with a seed that replays it exactly. After the fix, 2,000 membership seeds and 4,000 chaos seeds run clean — and the same simulator later found a second bug in how new nodes learn return addresses.
