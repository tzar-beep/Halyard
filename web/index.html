The Redis protocol,
replicated with Raft.

Halyard speaks RESP, so redis-cli and your existing clients just work. Every write is replicated to a majority and on disk before it's acknowledged — a server can die at any moment and no confirmed write is lost.

    How it's tested

    run any of these from the repo root

    Correctness claims are only as good as the tests behind them. Each card ends with the command that reproduces it.

    Deterministic simulation2,000+ seeds · pass

    Message loss, duplication, reordering, partitions, crashes mid-fsync, compaction and leadership transfer. Election safety and state-machine safety are checked after every step. Found two real bugs before release.

    SEEDS=2000 go test ./internal/raft
    Linearizability under faults~15k ops · linearizable

    Clients read and write a real TCP cluster while a nemesis partitions and kills nodes; the history is checked with a Wing–Gong/Lowe search. With ReadIndex disabled, the same test fails.

    JEPSEN_SECONDS=30 go test -v ./tests/jepsen
    Differential testing400k commands · identical

    Random command streams go to Halyard and to Redis 7 and every reply is compared byte for byte. It also found an index-truncation bug in Redis's own LSET.

    REDIS_ADDR=127.0.0.1:6400 go test ./tests/differential
    Fuzzing5 targets

    RESP parser, Raft message codec, WAL recovery, snapshot and key-dump decoders.

    go test ./internal/resp -fuzz FuzzReadCommand

    Run it

    Docker or Go 1.22+
    # three nodes, separate disks; any node accepts clients and redirects to the leader
docker compose -f deploy/docker-compose.cluster.yml up -d --build
redis-cli -c -p 6381 SET hello world
redis-cli -p 6381 INFO replication
    # one node, append-only file fsynced every second
go run ./cmd/halyard -addr :6379 -appendfsync everysec
redis-cli SET hello world
    # three Raft groups own the 16,384 hash slots; leaders spread across nodes
halyard -id 1 -shards 3 -cluster 1=h1:7000/h1:6379,2=h2:7000/h2:6379,3=h3:7000/h3:6379
redis-cli -c -h h1 CLUSTER SLOTS
redis-cli -c -h h1 CLUSTER MIGRATE 5000 2   # move a slot while serving traffic
